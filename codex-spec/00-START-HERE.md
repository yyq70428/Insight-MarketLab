# MarketLab 產品規格總覽

## 用途

本目錄定義 MarketLab 的產品功能、資料邊界、使用者介面、系統行為、服務契約、部署條件與驗收標準。

各文件共同構成目前產品版本的完整規格，功能行為與視覺呈現均以本目錄的定義為準。

## 產品目標

MarketLab 是深色金融分析與回測工作台，支援美股、台股與加密資產。核心任務為：

- 瀏覽 K 線、成交量、RSI、MACD、ZigZag、諧波型態與支撐壓力。
- 使用歷史錨點隔離未來資料，執行技術面與新聞面分析。
- 將兩份第一層報告交給決策 Agent，產生買進、賣出或觀望決策。
- 決策完成後才讀取錨點之後的 K 線，進行紙上交易驗證。
- 儲存每輪 session、Agent 報告、策略版本、影子測試與自適應審核。
- 執行單次完整 Flow，或在指定日期區間內進行逐交易日序列回測。

## 頁面

| 路由 | 用途 |
| --- | --- |
| 根路由 | 主圖表、回測錨點、Agent Flow、區間序列回測與側欄報告 |
| scanner | 多標的諧波型態掃描、篩選與進度 |
| stock | 個股圖表、公司資料、台灣與國際新聞 |
| quant | 單標的滾動驗證與離線研究快照 |
| dashboard | session、Agent run、策略版本、影子評估與自適應事件後台 |

## 不變條件

1. 錨點前的分析階段不得取得任何錨點後欄位、行情或事件。
2. 決策必須在讀取未來驗證 K 線之前完成並凍結。
3. 技術與新聞可並行；決策、驗證、自適應必須依序。
4. 區間回測必須等前一輪完整結束後，才建立下一輪。
5. 模型不得補寫新聞、引用不存在的來源或將歷史結果稱為勝率。
6. 自適應候選不得立即覆寫正式版本，必須經後續、不重疊的影子樣本驗證。
7. MongoDB 是 Flow 與策略審計的必要儲存，不可靜默降級為記憶體。
8. 金鑰、密碼、webhook 與含帳密的連線字串不得進入版本控制或前端回應。
