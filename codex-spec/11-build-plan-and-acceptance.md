# 11 — 建置順序與驗收規格

## 建置順序

### 階段一：專案骨架與環境

建立應用、前端、後端、Flow、測試、部署、量化與結果目錄。完成單一設定層、範例環境檔、版本忽略與映像忽略規則。

驗收：實際環境檔不被追蹤，範例機密全部為空，應用可讀取預設值。

### 階段二：市場資料與基礎 API

完成代號驗證、搜尋、報價、K 線、公司資料、一般新聞與快取。

驗收：美股、台股與加密資產的代號正規化正確；錨點 K 線沒有後續資料；不合法輸入被拒絕。

### 階段三：分析引擎

完成轉折點、ZigZag、諧波型態、潛在反轉區、目標價、支撐壓力、RSI 與 MACD。

驗收：高低轉折交替；型態比例與方向正確；區間數與型態數受上限控制；圖表可完整渲染。

### 階段四：主介面

依 HomePageUI 建立頂欄、工具列、主圖、RSI、MACD、右側欄、搜尋、諧波疊圖與支撐壓力疊圖。

驗收：比例與參考圖一致；所有按鈕可使用；副圖不過大；桌面、中型與行動畫面無溢出。

### 階段五：錨點與單次 Agent Flow

完成錨點日期、技術 Agent、歷史新聞擷取與驗證、新聞 Agent、決策 Agent、紙上交易、未來 K 線播放與自適應 Agent。

驗收：決策前不存取未來資料；兩份報告身分不同時被拒絕；新聞來源無效時不計分；每階段完成就立即顯示；重複執行不產生第二份 champion。

### 階段六：持久化、版本與後台

完成 MongoDB collections、session 狀態機、job、Agent run、策略基準、session 覆寫、候選、影子測試、發布、回滾、新聞評審與後台。

驗收：所有報告可依 session 查詢；版本差異可稽核；錨點不會選到未來版本；候選未通過後續樣本前不會成為正式版本。

### 階段七：區間序列回測

完成批次設定、交易日錨點、逐輪執行、進度、成功率、HOLD 波動驗證、前後 session 關係與重新載入恢復。

驗收：單批次最多 94 個日曆日；最長持有限於 1 至 7 個交易日；前一輪 adaptive 未完成時不得建立下一輪；後續輪次可使用已生效的新版本，不被初始參數覆蓋；HOLD 只在雙向最大波動都未超過門檻時成功。

### 階段八：掃描、告警、個股與量化

完成背景掃描、篩選、Discord 告警與去重、個股雙新聞欄、單標的即時量化回測與離線快照。

驗收：單標的失敗不中斷掃描；掃描進度逐步顯示；告警冷卻有效；量化訊號沒有 look-ahead；滾動驗證區段不重疊。

### 階段九：容器與安全

完成 app、PostgreSQL 與 MongoDB 編排、健康檢查、volume、本機綁定、密碼注入與建置排除。

驗收：應用可從 9011 與 9012 存取；PostgreSQL 使用 9013；MongoDB 不對外暴露；重建 app 不遺失資料；實際環境檔與機密不存在於版本或映像。

## 必須自動測試的邊界

- 錨點後資料不進入技術、新聞或決策輸入。
- 模型失敗不會靜默回退到技術訊號。
- 新聞來源識別值不可被偽造、重複或重新分類。
- 同根 K 線同時觸及目標與停損時使用保守停損。
- HOLD 的上下行最大波動及門檻邊界。
- 權重正規化、全零權重、MACD 平坦、RSI 模式與支撐壓力模式。
- 階段幂等、同角色唯一、失敗狀態、版本 revision 衝突與回滾。
- 影子樣本非重疊、生效時間、最小樣本、改善門檻與忠實度門檻。
- 批次第二輪只保留批次的持有與 HOLD 限制，其他參數使用當時正式版本。

## 最終驗收

全部自動測試通過，容器內的完整測試套件不得有失敗。至少進行一次真實 MongoDB 單次 Flow 整合測試，以及一次至少兩個交易日的區間序列測試，並確認第二輪不會提前建立。

最終專案不得含實際機密、追蹤的環境檔、本地資料庫、快取、編譯產物或不必要的產生結果。
